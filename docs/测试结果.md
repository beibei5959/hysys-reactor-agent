## 自动化测试

本轮环境：Windows，Python 3.14.3；Pydantic 2.13.5、LangGraph 1.2.12、httpx 0.28.1、pytest 9.1.1、python-dotenv 1.2.4。

执行：`python -m pytest -q -p no:cacheprovider`。

**60 passed in 0.48s**。无在线调用，测试独立于模型服务和 HYSYS 安装。

覆盖范围：ReactionInfo 数值/未知值/矛盾校验；三场景与选择优先级；高温不触发 Gibbs；模型 JSON 契约；模拟参数约束；缺参不运行；未收敛不出结果；有限重试与恢复；未验证 API 不重试；每轮状态隔离；控制器调用顺序和异常释放；离线三场景端到端；模型降级顺序、超时/HTTP/格式错误、配置跳过、全部失败停止、空正式回答降级、密钥脱敏、解释降级。

另以真实 CLI 运行三个离线场景及 JSON 输出：均完成正确选型，结果来源为 Mock，converged=null、engineering_results=null。23 个 Python 文件语法检查通过（后续仅扩充测试用例，文件数未改变）。

## 真实模型联调

首轮五用例：平衡、转化、吉布斯三场景均 success（Mock）；缺参场景与仅高温场景均 needs_input。记录见 `模型降级实测记录.json`。当时本地 schema 模式产生空正式回答，按设计降级到 DeepSeek；DeepSeek 实际成功，不因模型列表未列出而预先禁止调用。

随后本地改用 text 模式、正式回答 JSON 校验，复验详情见 `在线模型联调结果.json`。该文件保存真实提取信息、规则结论、运行状态及各提供商轨迹。JSON 契约可以检测格式问题，不能证明语义绝对正确。

最终五例全部通过：三场景正确选型并完成 Mock；缺参/仅高温均阻断执行。五次解析均在本地超时后由 DeepSeek 完成；转化场景和仅高温场景的解释由本地完成，其余解释在本地超时后由 DeepSeek 完成。因此当前本地完整解析速度仍不满足默认超时，本轮证明的是降级后的链路可用，不能宣称本地独立完成所有场景。

硅基流动首次提取超时；关闭其思考模式后复验成功，识别转化率为 0.8，见 `硅基流动连通验证.json`。这是第三提供商单独连通/提取验证；本地与 DeepSeek 同时失败后调用第三家的顺序由模拟 HTTP 测试验证，不声称现场三家连锁故障已全部制造验证。
