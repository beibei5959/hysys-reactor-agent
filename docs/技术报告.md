# HYSYS Reactor Agent：架构、仿真方法与验证结果

本项目探索如何将自然语言入口、可解释的反应器选型规则与 Aspen HYSYS 自动化接口连接起来，形成“输入工艺描述 → 选择模型 → 执行仿真 → 返回并核验结果”的工作流。当前实现面向三个可复现示例：甲烷蒸汽重整、甲苯歧化和简化碳–水气化。

项目定位为研究与学习原型。真实计算通过 Windows 上的 HYSYS V15 COM 接口完成；Web 界面使用 Mock 数据演示交互。运行真实仿真需要用户自行安装并具备可用的 HYSYS 授权。

## 1. 架构与技术选择

Python 负责数据处理与 COM 调用，LangGraph 组织参数校验、模型选择、仿真执行和结果解释。将流程控制与仿真执行分开，便于独立排查自然语言解析、模型配置和求解过程中的问题。

```text
UTF-8 工艺描述文件
  └─ run_nl.py
      ├─ 匹配示例：使用固定结构化预设
      └─ 未匹配：进入 LLM 参数提取路径
          ↓
      app.py / LangGraph：校验 → 规则选型 → 工具分派
          ├─ Conversion：COM 适配器更新已激活的甲苯参考案例
          └─ Equilibrium / Gibbs：子进程调用专用建模与验证脚本
              ↓
          HYSYS 计算 → 结果检查 → JSON 输出
```

核心实现见 [自然语言入口](../run_nl.py)、[选型规则](../src/knowledge/reactor_rules.py)、[工具分派](../src/tools/hysys_tools.py) 和 [专用脚本调度](../src/hysys/verified_runners.py)。

**自然语言入口当前有明确的能力边界。** 命中示例关键词时，使用预设参数，而非逐项提取并采用用户文本中的数值；因此，修改描述中的温度或流量不保证改变仿真条件。未命中的描述可进入 LLM 提取路径，但三个示例的成功记录不能证明任意工艺描述均可自动建模。专用重整、气化脚本也使用自身定义的工况，尚未形成通用参数化执行接口。

## 2. 反应器选择与执行方式

选型采用显式规则，并在结果中保留 `selection_reason`。规则依次判断：已知转化率时选择 Conversion；反应路径已知、可逆且受平衡控制时选择 Equilibrium；多反应体系中路径或产物分布不明确时选择 Gibbs；信息不足则返回缺失依据。

| 示例 | 选择依据 | 当前执行方式 |
|---|---|---|
| 甲烷蒸汽重整 | 已知重整与水煤气变换两条可逆反应，比较不同温度的平衡组成 | 自动创建案例，使用 HYSYS 反应库的平衡常数关联参数 |
| 甲苯歧化 | 明确指定甲苯转化率为 50% | 核对既有参考案例后写入进料、求解并检查结果 |
| 简化碳–水气化 | 在指定候选物种集合内求解多反应平衡 | 自动创建 Gibbs 案例，候选物种为 C(s)、H₂O、CO、CO₂、H₂ |

Gibbs 路径仍需事先定义候选物种；选择 Gibbs 并不意味着系统可以自动发现所有可能产物。甲苯通道则依赖已配置的参考案例，其进料更新能力与从零创建模型的能力应分别理解。

## 3. 接口联调与验证设计

开发中主要解决了三类问题：

- **COM 对象与单位不一致。** 区分集合属性和方法，使用实际可访问的组件路径，并通过带单位的 `GetValue` / `SetValue` 读写。质量流量与摩尔流量换算采用 HYSYS 数据，减少手工舍入引起的检查偏差。
- **求解状态与结果读取时序。** 建模和验证采用分阶段执行；轮询结果并检查连续稳定性，避免刚写入参数就读取旧值。不同执行器的检查项并不完全相同，具体以诊断记录为准。
- **平衡参数的来源与精度。** 重整示例采用 HYSYS 内置反应库导出的完整精度参数，并核对温度范围、分压基准和单位，避免直接抄录界面上经过舍入的系数。

验证覆盖输入条件、反应器配置、质量或元素衡算，以及场景相关指标。重整额外比较反应商与平衡常数；甲苯核对实际转化率和化学计量；气化检查碳转化率范围、元素守恒及剩余固碳。稳定性与衡算通过是计算一致性的证据，不能单独证明物性方法、物种集合或工程假设适用于实际装置。

AI 编程工具用于辅助接口探索、脚本实现和错误排查；接口行为与计算结论通过 HYSYS 帮助资料、实际运行和数值检查确认。运行时的示例路由与选型由预设和规则完成，并不要求每一步都调用大模型。

## 4. 已记录的运行结果

下表摘自仓库中的历史运行记录，数值按展示精度舍入。它们描述指定工况下的结果，不代表在其他机器或其他输入下重新运行的保证。

| 示例与计算基准 | 主要结果 | 结果记录 |
|---|---|---|
| 重整：CH₄ 100 kmol/h、蒸汽 270 kmol/h；入口 520℃，13.5 bar 绝压；出口分别为 600℃、710℃ | 甲烷转化率分别为 30.22%、55.06%；对应结果中的平衡与衡算检查通过 | [重整 JSON](../queries/scenario1_reforming.result.json) |
| 甲苯：10000 kg/h，380℃，2.5 MPa，指定转化率 50% | 实际转化率 50.0%；苯约 27.1324、邻二甲苯约 27.1338 kmol/h；质量残差为记录精度下的 0.0 kg/h | [甲苯 JSON](../queries/scenario2_toluene.result.json) |
| 碳–水：1000 kg/h 浆料，62 wt% 固碳；入口 40℃、出口 1400℃，40 bar 绝压 | 碳转化率及 CO 收率约 40.86%；气相 CO/H₂ 摩尔比约 1:1；剩余固碳约 30.5258 kmol/h | [气化 JSON](../queries/scenario3_gasification.result.json) |

CO 收率按“出口 CO 中的碳摩尔流量 / 进料碳摩尔流量”定义。气化 JSON 的 `outlet_mole_fractions` 将剩余固碳计入总摩尔流量，因此 CO、H₂ 各约 29%；仅对气相归一化后，两者各约 50%。

重整记录中，Agent 的 `simulation_inputs.feed_flow_kmol_h` 为 100，而执行脚本采用的总进料为 370 kmol/h；上表采用实际脚本基准。该元数据差异需在后续统一，当前不能仅根据顶层输入字段解释绝对产量和热负荷。

## 5. 适用范围与复现

甲苯模型将二甲苯产物统一表示为邻二甲苯，未预测邻、间、对异构体分布。重整模型仅包含两条指定反应，未考虑积碳。气化模型以纯固碳代替煤，不含甲烷等烃类候选物种，也未加入氧气进料；其结果仅适用于该简化体系。原始示例中的 80000 Nm³/h 缺少明确基准，当前未将其换算为绝对产量。

复现需在 Windows 上安装项目依赖并保持 HYSYS 运行。甲苯示例还需激活配置匹配的 `toluene_python_test.hsc`。在仓库根目录、已配置的 Python 环境中运行：

```powershell
python -X utf8 run_nl.py queries/scenario1_reforming.txt
python -X utf8 run_nl.py queries/scenario2_toluene.txt
python -X utf8 run_nl.py queries/scenario3_gasification.txt
```

运行前提及更多说明见 [README](../README.md)。结果应结合退出码、诊断时间、逐项检查和实际案例一起核对。历史 JSON 中的案例路径来自开发工作站，不代表本机已有对应文件。Web 演示的配置说明见 [README-WEB](../README-WEB.md)；当前 Web 后端固定使用 Mock，尚未接入真实 HYSYS 通道。

## 6. 后续改进

优先完善现有执行链的可复现性：统一预设与脚本的参数来源；为每次执行绑定唯一诊断文件，并将子进程失败作为失败返回。目前调度器按修改时间读取最新报告，存在复用旧报告的风险，需要补上本次运行关联检查。

在此基础上，再扩展任意工况参数传递、二甲苯异构体分配及更完整的煤组成与气化物种集合，并为各项扩展增加独立验证记录。当前版本提供的是三个受约束示例的实现与运行证据。
