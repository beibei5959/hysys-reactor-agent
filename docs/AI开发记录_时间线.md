## AI 协作方式说明

本项目采用**人工主导设计与决策、AI 编程助手结对实现**的分工模式：

- **架构与框架选型由人工确定**：两层结构（原始 agent 层 + 集成层）、LangGraph 五节点
  工作流（解析 → 选型 → 校验 → 执行 → 解释）、COM `GetActiveObject` 附着运行中实例的
  连接方式、Mock/真机双通道、Web 前后端分离与 SQLite 任务存储——均为设计阶段定下的
  框架级决策，AI 助手按此实现；
- **关键工程策略由人工拍板**：三个目标场景采用"确定性关键词 → 固定预设"路由
  （可靠性优先于 LLM 自由提取）；场景 2 的"写前守卫 + 复用已验证参考案例"；
  真机收敛采用"连续 3 次轮询全检查通过 + solver 空闲"判据；录屏证据链的三点自检设计；
  偏差与局限全部主动披露的原则；
- **AI 助手在人工指令下完成实现层工作**：代码生成与修改、COM 接口行为探索、真机报错
  排查、数值验算脚本、文档初稿；所有 AI 产出经人工复核，并以 result.json / .hsc / 录屏
  形成证据闭环后才作数，未验证不宣称成功；
- **人工执行与最终裁决**：远程工作站操作、HYSYS 案例状态与界面数值确认、录屏、
  入库与发布决策。

即：AI 提升实现与排错效率；系统怎么设计、判据怎么定、结论算不算数，责任在开发者。
