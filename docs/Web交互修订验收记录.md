# Web交互修订验收记录

## 已修复的交互问题

1. **历史区分**：原始分析与修订分别显示标签、原始任务编号和修订任务短编号；任务页显示修订层级，可打开上一版本。旧任务无需迁移即可读取父子关系。
2. **全量历史搜索**：新增经过账号归属校验的分页查询，每页20条；搜索全部有权限的任务描述及编号，不再局限最近100条。中文关键词按字面匹配，不将百分号当通配符。
3. **参数即时联动**：修改选型条件后，表单请求后端同一套工程规则并显示当前预选型。Conversion的转化基准、Equilibrium的平衡方法和反应方程栏立即变化，不需要先创建一份任务。上方卡片明确标注“已保存的选型结论”，避免混淆当前草稿与历史结果。执行前仍由后端完整复核。
4. **反应方程表单**：通过反应物/产物、组分、正数系数逐项编辑，可增删反应和组分；提交时转换成原后端计量映射，不改变数据契约。不再要求用户编写JSON。
5. **中文提示**：缺参列表、分析说明和错误信息中的常用字段名映射为中文；JSON导出仍保留原始字段，便于复现。
6. **状态准确性**：缺参时“参数校验”显示“发现缺项”，执行详情显示“等待补充参数”；待确认、失败、中断、结果待核对各有明确状态，不统一显示“流程结束”。
7. **模型等待**：新增LOCAL_LLM_TIMEOUT_SECONDS，默认15秒；云模型仍使用LLM_TIMEOUT_SECONDS，默认60秒。解析和解释均维持本地→DeepSeek→硅基流动的既定顺序。

## 在线联调发现并修复的问题

实际请求发现：DeepSeek默认思考过程占用了1024输出额度，finish_reason为length，正式content为空。针对结构化提取和中文解释请求，按官方接口使用 `thinking: {type: disabled}`，保持用户指定模型名、JSON格式约束及工程规则不变。

依据：[DeepSeek Thinking Mode官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。不读取思考内容作为正式答案。

修复后实测：

- 独立DeepSeek解析成功，约1.2秒；独立解释成功，约0.9秒。
- 网页任务解析阶段：本地约15秒超时，DeepSeek约1.4秒成功接替。
- 补齐参数后的完整任务：Mock流程completed，解释success；解释阶段本地约15秒超时，DeepSeek约0.8秒成功接替。
- 中间一次DeepSeek响应不符合契约时，硅基流动成功接替，证明第三级降级实际发生；最终修复后的任务无需第三供应商。
