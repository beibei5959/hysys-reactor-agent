# AI 驱动 HYSYS 反应器智能选择系统——本地阶段简报

## 问题与方案

用户用自然语言描述反应时，往往混合了反应机理、工况与计算目标。系统需要先辨别已知信息，再选择合适的反应器，避免仅凭“高温”等表面词语判断。后端统一使用 Python，以 Pydantic 约束输入，LangGraph 编排流程，工程规则保证核心选型可解释，HYSYS 承担最终真实计算。

核心规则保持固定：给定转化率选择转化反应器；具体可逆且受平衡控制的反应选择平衡反应器；复杂体系的路径或产物分布不明确时选择吉布斯反应器。信息不足时明确追问，不能默认选择吉布斯。

## 实现与工程判断

第一版工作流包含解析、选型、校验、执行和解释五个节点。状态中保存原始请求、结构化反应信息、选择理由、缺参列表、运行结果、错误与重试次数。输入不完整时跳过模拟；临时且可安全重试的错误最多追加两次；未验证接口和参数错误不重试。

控制器将工作流与 COM 隔离。Mock 完整执行建模接口的调用顺序，但只回显输入，真实组成、能耗和收敛信息均不伪造。真实控制器目前仅实现已确认的只读连接链路，其余建模接口明确阻断。这使本地开发与远程 API 核验可以按原定顺序推进。

模型接口可提取结构化 JSON 并补充中文解释，确定性规则仍独立执行。离线示例不用模型服务，输出明确标明输入来源。在线模型解释作为辅助内容保留人工核对要求，不覆盖原始规则或结果来源。

模型调用采用用户指定的降级顺序：本地 Qwen、DeepSeek、硅基流动。网络、超时、接口或数据契约错误才降级，工程缺参仍追问。各阶段每个模型最多请求一次，记录脱敏原因；所有解析服务失败则不执行模拟，解释服务失败不丢弃已有计算状态。

## 本地成果与证据

三种开发场景完成本地端到端运行。测试覆盖模型数值边界、规则优先级、高温不误选、缺参阻断、错误分支、有限重试、结果来源、资源释放与模拟 HTTP 契约；实际数量及环境记录见测试结果文档。

本阶段可以证明软件流程和约束逻辑成立，不能证明真实 HYSYS 模型精度、热力学正确性或在线模型分析质量。开发场景数值并非原始考试题，需取得题目后核对。
