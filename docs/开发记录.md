# 开发记录

0.2新增单机持久化任务服务与故障治理，当前交付状态以 [0.2版本验收记录](0.2版本验收记录.md) 和 README 为准。下文保留0.1版本实施历史。

## 本轮实施顺序

1. 读取参考对话与目录：没有已有项目文件；在 outputs/hysys-reactor-agent 建立交付项目，未删除用户文件。
2. 先落工程设计施工图，固定 Python 后端、三场景规则、五节点、状态字段和 COM 边界。
3. 建立 ReactionInfo、SimulationInputs 与 ReactorAgentState，通过数值/矛盾输入检查后继续。
4. 建立三场景开发 JSON 与规则，确认 Equilibrium、Conversion、Gibbs 顺序命中；模型/规则 20 项测试通过。
5. 建立 LangGraph 分支，以注入的测试执行器验证缺参、失败、有限重试等 8 项，通过后实现 Mock。
6. 接入控制器/工具层和 CLI，35 项测试及三场景端到端通过。
7. 增加模拟参数、模型 HTTP 契约和状态隔离测试，47 项通过。
8. 根据用户追加要求自动加载 .env；本地地址从 .11 改为 .10；密钥只保存在被忽略的 .env。
9. 根据用户确认实现固定降级：本地 → DeepSeek → 硅基流动。补充提供商顺序、超时、错误输出、失败上限与脱敏测试，共 56 项通过。
10. 真实模型联调：最初本地 json_object 请求被拒；json_schema 正式 content 为空，触发 DeepSeek 接手，五用例通过。随后改用本地 text 返回 JSON + 本机契约校验；最终记录见在线模型联调结果。
11. 最终回归：60 项自动化测试通过；在线五用例通过，本地解析超时后 DeepSeek 接手，本地两次解释成功。硅基流动在关闭思考后独立提取成功。最终压缩包排除 .env、缓存与验证环境，并扫描确认不包含提供的密钥。

## 边界与尚未完成事项

- 本轮没有访问远程考试机。真实 COM 建模、求解、收敛检查和结果提取均未完成，不冒充已验。
- 用户曾验证 GetActiveObject → ActiveDocument → Flowsheet；代码只实现该只读链路，实际重新探测留待考试机。
- 示例不是原始考试题，真实组分标识、物性适用性、反应集、元素守恒和操作规格须后续核验。
- 命令行是当前 Python 后端入口；没有增加未要求的网页、数据库或复杂框架。
- 真实模型通过有限开发用例，不代表对所有化工描述可靠；工程规则仍独立约束选型。
